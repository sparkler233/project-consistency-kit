恢复本次范围内足以判断下一步的信息。全程只读：不改文件、不修入口、不运行测试或实验、不操作提交或 synced。报告只覆盖实际读到的范围，不说成全项目核验。

## 1. 读入口

完整读取 `PROJECT.md` 与 `一致性机制/运行规则.md`。宿主已加载的规则不重读，没加载的必要规则自己读。

用户给了任务就沿任务恢复。只说 catchup 时，以 PROJECT 和 Git 概况完成恢复：入口列出的方向只报告有哪些，不逐项展开、不自选任务；为核对现状可以补读少量直接相关的资料、实现或测试。

## 2. 看 Git 概况

运行一个脚本取得全部 Git 概况，输出为 JSON：

```bash
node .agents/skills/wrapup/scripts/scope.mjs --overview
```

直接用输出中的值，不自己抄写哈希、不另算基线。

- 未提交与未跟踪文件只看脚本列出的名称、行数与大小(未跟踪目录附文件数与示例)，不读内容。
- `recent_commits` 只有标题，说明当时的事，现状以 `PROJECT.md` 为准；与任务相关时再 `git show` 读正文。
- `tree`、`top_files` 只看名称。
- 在非 canonical 分支上，`current_branch_state.task` 是本分支最近检查点的说明(目标、进度、还剩)及之后的提交，据此接着做；「还剩」不是「无」时任务没做完，为空时按提交标题与改动判断。主线自分叉以来的改动与本分支有交集、冲突或命中联动规则(`rules_hit_by_canonical`)时，才读相关改动，并在报告里说明；要不要同步主线由用户决定。

需要 diff 或更早历史时再展开。guard 不可用、未配置 canonical、没有首次提交或基线异常时，不猜替代基线，照常恢复其余资料并说明无法比较；`can_advance=false` 不影响读取。

## 3. 按需补读

沿阅读入口读当前任务的要求、限制、相关成果与验证依据，以完整章节为单位，保留条件与例外。背景和历史链接不递归展开；联动目录是收尾用的，不作恢复读取清单。

遇到以下缺口才继续查，先沿入口、再针对性搜索，不无限翻历史：

- 缺要求或完成标准：查对应正本。
- 资料与成果不符：核对相关成果、局部 diff 或必要历史；要求与实现不一致是差距，不必判定哪份过时。
- 依赖某个验证结论：确认它验证的是当前要求；旧条件下测试通过、或没发现变化，都不等于已验证。

查不清的关键缺口如实报告，不猜。入口缺失或链接失效时，用现有 README 等恢复能确定的部分，报告缺口，不修复。规则互相冲突时报告冲突及影响，不擅自选一份。未提交文件不能证明属于当前任务。

## 4. 报告

能回答这三个问题就停：现在要求什么、有哪些限制；相关工作做到哪里、哪些没核对；下一步做什么或被什么挡住。

报告简短，包含：

- 本次范围、关键结论及依据、下一步或阻塞。没核对的成果写“文档记载”；没发现问题只说“本次范围内未发现阻塞”。
- Git 分支与基线状态。
- “自上次收尾以来”(每次都有)：基线之后的新提交标题、未提交与未跟踪改动、「待提交」中未迁出的决策(`pending_decisions`，逐条写出)；都没有写一行“无变化”；基线不可靠时写无法比较。
- 在分支上：任务名、目标、进度、还剩(找不到检查点时注明)，以及主线变化是否与本分支相关。
- `other_branches`、`anomalies` 每项一行：分支写任务、还剩与是否已全部进主线；有未提交改动、还没进主线的决策、找不到检查点(`handoff_missing`)或与别的分支共有未进主线的提交(`shares_unmerged_with`)时注明；为空不写。

只调用 catchup 则报告后结束。同时授权了后续任务且没有阻塞，就直接继续，不追问；关键缺口未解时，不做依赖它的动作。
