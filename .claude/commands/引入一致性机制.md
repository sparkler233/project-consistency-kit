<!-- 一致性机制 version: 2026-08-18 -->

把【项目一致性机制】装进当前项目,或把旧版文件模型迁移到三层架构:

```text
README.md                  对外说明(可选,用户自有)
PROJECT.md                 项目事实正本
AGENTS.md                  Agent 指令唯一实体正本
CLAUDE.md -> AGENTS.md     Claude Code 相对链接适配
```

核心原则:

1. **增量 + 合并,绝不静默覆盖。** 先展示计划,用户确认后才写;替换实体 CLAUDE 前必须证明其中内容已迁入 PROJECT / AGENTS,无 git 历史时另存迁移备份。
2. **职责分离,不靠猜。** 项目事实进 PROJECT,工作规则进 AGENTS,README 保持用户原样;无法分类的段落列给用户决定。
3. **一个实体 + 一个链接。** AGENTS 是实体正本,CLAUDE 只能是相对链接 `AGENTS.md`;不维护双实体、不建立循环或仓库外链接。

> 套件源(只读):优先从全局命令符号链接反推出套件根;失败时尝试 `~/Developer/项目一致性机制`,仍找不到就询问用户。绝不修改套件源。

## 步骤 0 · 定位套件并探测目标

1. 确认套件源存在:
   - `.claude/commands/catchup.md`
   - `.claude/commands/同步.md`
   - `templates/PROJECT.md`
   - `templates/AGENTS.md`
   - `templates/一致性机制/文件联动目录.md`
2. `pwd` 等于套件根时停止:本命令用于目标项目,不是更新套件自身。
3. 探测 Git 与机制状态:
   ```bash
   git rev-parse --is-inside-work-tree 2>/dev/null
   git rev-parse -q --verify HEAD
   git rev-parse -q --verify refs/tags/synced
   git status --short 2>/dev/null
   grep -hE '^(<!-- |# )一致性机制 version:' .claude/commands/*.md 一致性机制/*.md 一致性机制/hooks/*.sh 2>/dev/null | sort -u
   grep -n '一致性机制:同步纪律 begin' AGENTS.md CLAUDE.md 2>/dev/null
   ```
4. 探测四份入口的**存在、文件类型与链接目标**:
   ```bash
   ls -l README.md PROJECT.md AGENTS.md CLAUDE.md 2>/dev/null
   test -L AGENTS.md && readlink AGENTS.md
   test -L CLAUDE.md && readlink CLAUDE.md
   ```
5. 完整读取现有 `PROJECT.md`、实体 `AGENTS.md`、实体 `CLAUDE.md` 与 README 的相关结构,建立“内容归属表”:
   - 项目背景、流程、地图、阶段、近期决策 → PROJECT;
   - 工作约定、质量规则、权限边界、同步纪律 → AGENTS;
   - 面向用户的介绍、安装、API、使用说明 → README 原位保留;
   - 无法可靠分类 → ❓列给用户,不要擅自移动。

## 步骤 1 · 判定入口迁移路径

| 当前状态 | 计划 |
|----------|------|
| AGENTS / CLAUDE 都不存在 | 从模板创建 AGENTS,再创建 `CLAUDE.md -> AGENTS.md` |
| 只有实体 AGENTS | 保留内容并补同步纪律;创建 CLAUDE 链接 |
| 只有实体 CLAUDE | 把事实迁入 PROJECT、规则迁入 AGENTS;核对无遗漏后以链接替换 CLAUDE |
| 两者都是实体 | diff + 语义合并;AGENTS 留规则,事实进 PROJECT;核对后以链接替换 CLAUDE |
| `AGENTS.md -> CLAUDE.md` | 旧版反向链接:读取 CLAUDE 实体并拆分;最终翻转为 AGENTS 实体 + CLAUDE 链接 |
| `CLAUDE.md -> AGENTS.md` | 正确方向:验证相对目标和内容职责;缺什么补什么 |
| 其他链接目标 / 循环 / 断链 | 标 ❌,列出真实目标,等待用户确认修复 |

替换现有实体 CLAUDE 的安全条件:

- PROJECT 与 AGENTS 已写好;
- 展示“原 CLAUDE 每个一级 / 二级章节 → 新落点”对照,无未归属章节;
- Git 已跟踪原文件时,确认 diff 可恢复;没有可恢复 commit 时,先把原文备份到 `一致性机制/迁移备份/CLAUDE.md`;
- 用户再次确认后才删除实体并执行 `ln -s AGENTS.md CLAUDE.md`。

## 步骤 2 · 拟订总计划 → 用户确认

计划表逐项标记:新建 / 合并 / 迁移 / 更新 / 跳过 / 询问。

```text
引入 / 迁移计划
┌──────────────────────────────────┬────────────────────────────────────────┬────────┐
│ 目标                             │ 动作                                   │ 状态   │
├──────────────────────────────────┼────────────────────────────────────────┼────────┤
│ PROJECT.md                       │ 新建或合并项目事实                      │ …      │
│ AGENTS.md                        │ 新建或合并工作规则 + 同步纪律           │ …      │
│ CLAUDE.md                        │ 内容迁移核对后替换为 → AGENTS.md        │ …      │
│ README.md                        │ 默认不动;仅判断是否加入 Part A          │ 跳过   │
│ .claude/commands/(catchup/同步)  │ 从套件新建或按版本更新                  │ …      │
│ 一致性机制/(文档 + hooks)        │ 从套件新建或按版本更新                  │ …      │
│ 文件联动目录.md                  │ 从分发模板新建或逐条合并通用规则        │ …      │
│ .claude/settings.json            │ 增量接线 Stop hook                     │ …      │
│ 项目自定中枢 / 领域规则          │ 扫描候选后询问                          │ …      │
│ .gitignore / .gitattributes      │ 按项目二进制类型询问                    │ …      │
│ synced tag                       │ 不存在时打在当前 HEAD                   │ …      │
└──────────────────────────────────┴────────────────────────────────────────┴────────┘
```

必须先问:

- 无法分类的旧 CLAUDE / AGENTS 内容放哪里;
- README 是否承载需要同步维护的公开契约(若是,加入 Part A;仍不把它当项目地图);
- 项目是否含图片、设计稿、字体或媒体;
- 不是 Git 仓库时是否允许 `git init`。

## 步骤 3 · 建立 PROJECT

- 已存在 → 保留结构,只补缺失的事实类别;绝不套模板重排。
- 不存在但旧 CLAUDE / README 有项目事实 → 基于这些内容新建,逐节标明来源;README 原文不动。
- 完全没有可迁移事实 → 从 `templates/PROJECT.md` 新建,再按仓库实际结构预填可确认的目录与入口;不臆造阶段或决策。
- 决策规范落点固定为 PROJECT“关键决策记录”;已存在其他 ADR / 决策日志可同时保留,但 PROJECT 留近期审计线索。

## 步骤 4 · 建立 AGENTS 与 CLAUDE 适配链接

**AGENTS.md**

- 不存在 → 从 `templates/AGENTS.md` 新建,再合并旧 CLAUDE 中识别出的工作规则。
- 已存在实体 → 原结构不动;以 `templates/AGENTS.md` 的 begin/end marker 块为正本:
  - 无 marker 且无“同步纪律” → 按语义挂到工作约定附近,否则追加到末尾;
  - marker 同版 → 跳过;
  - marker 旧版 → 询问后只替换 marker 块内内容,块外一字不动;
  - 无 marker 但已有手写“同步纪律” → 标 ❓人工合并,不自动叠加第二份。
- 已是链接 → 先按步骤 1 解析,不得在链接链条上继续叠加链接。
- 同步纪律的决策落点必须是 PROJECT,`/catchup` 必须明确不重复读取 AGENTS / CLAUDE。

**CLAUDE.md**

- 正确状态只有一种:`CLAUDE.md` 是相对链接 `AGENTS.md`。
- 新建链接:`ln -s AGENTS.md CLAUDE.md`。
- 已有实体或错误链接 → 只有满足步骤 1 的迁移安全条件并再次确认后才替换。
- 创建后验证:
  ```bash
  test -f AGENTS.md
  test -L CLAUDE.md
  test "$(readlink CLAUDE.md)" = "AGENTS.md"
  cmp AGENTS.md CLAUDE.md
  ```

> 当前只设计和验证符号链接路径;Windows 回退方案暂不自动实施。

## 步骤 5 · 拷入 / 更新项目无关机制件

不存在才新建;已存在时比较统一版本行,用户同意才更新:

- `.claude/commands/catchup.md`、`.claude/commands/同步.md`
- `一致性机制/机制设计说明.md`、`一致性机制/README.md`
- `一致性机制/hooks/收尾提醒.sh`(随后 `chmod +x`)
- `一致性机制/决策档案.md`:已有归档内容绝不覆盖
- `一致性机制/LICENSE.project-consistency-kit`:从套件根 `LICENSE` 新建;已有则不覆盖,避免把套件许可证放到目标项目根而误解为整个项目许可证

`一致性机制/文件联动目录.md` 的来源必须是**套件 `templates/一致性机制/文件联动目录.md`**,不是套件自身的真实联动目录:

- 目标不存在 → 从模板新建;
- 已存在 → 不整文件覆盖,按通用规则逐条补缺;保留项目自定中枢和规则。

`.claude/settings.json`:

- 不存在 → 按套件内容新建;
- 已存在 → 只向现有 JSON 的 `hooks.Stop` 追加收尾提醒 entry;
- 已含“收尾提醒” → 跳过;不覆盖用户已有 hooks。

## 步骤 6 · 发现项目中枢与领域规则

1. 扫描已跟踪文件、顶层与常见文档目录。
2. PROJECT 与 AGENTS 固定进入 Part A。
3. README 只有承载公开安装 / API / 使用契约且用户确认时才进入 Part A。
4. 列出 ADR、spec、schema、contract、大纲、风格定义等候选,说明“为什么像中枢 + 应随什么更新”,由用户选择。
5. 询问是否有稳定的“改 A 必查 B”领域规则,确认后写入项目自定规则区。

## 步骤 7 · 二进制策略

- 含图片 / 设计稿 / 字体 / 媒体 → 将套件 `.gitignore` / `.gitattributes` 相应缺失规则追加到目标;需要 LFS 时提醒首次 add 前运行 `git lfs install --local`。
- 纯代码 / 纯文字 → 跳过 LFS,最多补系统 / 工具忽略规则。
- 同名配置只补缺失行,绝不覆盖或删除用户规则。

## 步骤 8 · 立 synced horizon

- 不是 Git repo → 只有用户同意才 `git init && git branch -M main`。
- 有 commit 且无 `synced` → `git tag synced` 打在当前 HEAD,既往历史不追溯联动。
- 无 commit → 先展示待提交范围与 message,用户确认后才首 commit + tag。
- 已有 `synced` → 不动。

## 步骤 9 · 报告与验证

报告新建、合并、迁移、跳过、失败与待填项,并给出 synced 所在短 hash。至少验证:

- PROJECT 可独立说明背景、地图、阶段与近期决策;
- AGENTS 是实体,CLAUDE 是正确相对链接且 `cmp` 一致;
- `/catchup` 读取 PROJECT,不重复读取 Agent 指令;
- README 即使不存在或完全改写,catchup / 同步仍能运行;
- Part A 已登记项目真实中枢;
- 跑一次 `/catchup` 能输出无旧职责警告的报告。

## 守则

- 先计划、后确认、再写入;替换实体 CLAUDE 前二次确认。
- 不丢旧内容、不以“模板更标准”为由重排用户文档。
- README 用户自有,默认不写、不创建、不作为项目地图。
- AGENTS 是唯一指令实体;CLAUDE 只做相对链接适配。
- PROJECT 是项目事实与近期决策正本。
- 不擅自 `git init`、commit 或 push。
- 套件源只读;文件联动模板与套件真实规则不得混用。
