# 示例：恢复并收尾一次内容项目

下面的输出是简化示意，用来说明两个仓库级 Skill 如何配合。Codex 使用 `$catchup` / `$wrapup`，Claude Code 使用 `/catchup` / `/wrapup`；具体内容会随项目文档、Git 状态和联动规则变化。

## 场景

一个图文内容项目刚调整章节结构，并新增两张插图。上次会话里已拍板“第三章插图采用跨页版式”，这条决策已经写进 `PROJECT.md`「待提交」；素材清单尚未登记新插图。

## 新会话执行 catchup

```text
项目概况
图文内容项目处于版式调整阶段，当前工作集中在第三章结构和插图接入。

自上次收尾以来
- 1 个新提交：第三章正文改为三节。
- 工作区：content/ch03.md 已修改；images/ch03/ 下新增 2 个未跟踪文件。
- 「待提交」有 1 条决策：第三章插图采用跨页版式。

下一步建议
1. 完成第三章渲染检查。
2. 收尾时执行 wrapup，登记新插图并迁出跨页版式决策。
```

catchup 先读 `PROJECT.md`、运行规则和脚本给出的 Git 概况，只汇报状态，等待下一步指令；需要细节时再按 PROJECT 阅读入口去读对应文档。

## 完成工作后执行 wrapup

wrapup 把计划、文件清单和完整提交说明一次展示出来：

```text
维护计划
- images/ch03/_manifest.md：登记两张插图的用途、来源与授权。
- PROJECT.md：迁出决策 12，「最近决策」删去最老的 1 行（全文已在 git），迁出后 10 行。

拟提交文件
- content/ch03.md（已修改）
- images/ch03/figure-01.png、figure-02.png（新建未跟踪，走 LFS）
- images/ch03/_manifest.md（已修改）
- PROJECT.md（已修改）

提交说明
第三章插图接入并登记素材,采用跨页版式〔决策 12〕

决策 12 · 2026-09-20 · 第三章插图采用跨页版式
  决定:第三章两张插图跨页排版。
  理由:单页排版时图注被截断。

Decision: 12

synced:提交完成、工作区干净后推进。回复“确认”执行。
```

用户确认一次后，wrapup 写入文件、提交，并按固定格式报告：

```text
wrapup 结果
- ✅ 已完成:登记两张插图;迁出决策 12
- ⏭️ 跳过:无
- ❌ 失败:无
- ⚠️ 必要但未完成:无
- ❓ 未核对范围 / 联动目录未覆盖:无
- 📌 提交:3f2a9c1;synced:已推进
- 业务遗留:第三章渲染检查
```

只有 canonical branch 通过确定性 guard 后才推进 `synced`；feature branch 只保存 checkpoint，决策留到合并回 canonical 后迁出。远端推送仍由用户手动完成。
