# 文件联动目录

<!-- 一致性机制 version: 2026-08-18 -->

> 本文件是新项目使用的联动规则骨架。定义“某个文件变了,还要检查哪些其他文件”。
> `/同步` 读取目标项目根 `一致性机制/文件联动目录.md`;套件仓库自身的真实规则不随模板分发。

## 怎么用这份目录

`/同步` 拿到自 `synced` 以来的所有改动后:

1. 比对 Part A 中枢文档清单;
2. 比对 Part B 例外规则;
3. 两者都没命中时,由 AI 判断隐性联动;
4. 新发现的稳定关系补进 Part B。

## Part A · 中枢文档清单

| 中枢文档 | 它应随什么改动而更新 |
|----------|--------------------|
| `PROJECT.md` | 项目背景、范围、流程、里程碑、目录、入口、当前阶段或决策变化 |
| `AGENTS.md` | Agent 工作约定、质量标准、权限边界或同步纪律变化 |
| `一致性机制/文件联动目录.md` | 出现新的稳定联动关系 |
| `一致性机制/机制设计说明.md` | 一致性机制本身发生真实变化 |
| 〔项目自定中枢文档〕 | 〔在此登记 API 契约、ADR、大纲、风格规范等关键文档〕 |

> `README.md` 不再是机制默认中枢。若它承载公开安装、API 或使用契约,按项目需要把它作为自定中枢加入本表。
> 中枢清单宜保持 4–10 个,变化慢、好枚举。

## Part B · 通用规则

### 规则 1 · 机制件变化 → 机制文档与公开契约

**触发**:`.claude/`、`一致性机制/hooks/` 或其他机制实现发生变化。
**动作**:
- 检查 `一致性机制/README.md` 与 `机制设计说明.md` 是否需要更新;
- 检查 `PROJECT.md` 的机制入口或项目地图是否受影响;
- 只有 README 确实公开描述了该行为时才更新 README。

### 规则 2 · B 类决策落地

**触发**:safety net 捕获到对话中的决策。
**动作**:规范落点是 `PROJECT.md`“关键决策记录”;写入前按日期 + 摘要前缀防重复。操作性内容同时改写到 PROJECT 正文或对应领域文档。

### 规则 3 · 项目结构或入口变化 → PROJECT

**触发**:目录、关键文件、常用命令、产物位置或项目阶段发生变化。
**动作**:更新 `PROJECT.md` 对应地图或状态;README 只有在公开展示同一变化时才联动。

### 规则 4 · 收到外来二进制 → 写 Markdown 摘要

**触发**:项目出现外来的 `.docx`、`.pdf` 或其他无法文本 diff 的二进制。
**动作**:在同目录写 `.md` 摘要;原件按项目二进制策略处理。

### 规则 5 · 素材 / 大文件目录变化 → manifest 对账

**触发(条件)**:本轮改动落在含二进制的素材 / 大文件目录,或 LFS 指针变化。
**动作**:对账 `_manifest.md`,只维护用途 / 来源 / 授权或版权(视觉项目可加风格基准);纯文字同步跳过。

### 规则 6 · 决策记录超限 → 轮转归档

**触发(条件)**:`PROJECT.md`“关键决策记录”超过 10 条。
**动作**:把最老条目剪切到 `一致性机制/决策档案.md`,PROJECT 只留最近 10 条和档案指针;按日期 + 摘要防重复。

### 规则 7 · Agent 指令变化 → 适配链接完整性

**触发**:`AGENTS.md` 内容变化,或 `AGENTS.md` / `CLAUDE.md` 文件类型变化。
**动作**:确认 `AGENTS.md` 是唯一实体正本,`CLAUDE.md` 是相对链接 `AGENTS.md`;不得存在双实体、循环链接或仓库外链接。
