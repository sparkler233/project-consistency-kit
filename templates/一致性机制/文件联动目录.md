# 文件联动目录

<!-- 一致性机制 version: 2026-09-30 -->

> 定义“改变什么，还需检查哪里”。按项目实际关系填写，删除不适用的示例；没有额外关系不编造规则。信息归属和阅读入口见 PROJECT，本目录不规定 catchup 全文必读列表。

wrapup 用范围脚本取得基线以来的变化与工作区状态后，用这里的触发条件检查必要联动；脚本按「项目联动关系」中每条规则触发里用反引号写的路径，列出本次改动命中的规则；没有路径可比、或路径之外还有文字条件的规则由 wrapup 自行判断。命中表示需要核对，不代表必须改文件；已发现的直接依赖不得遗漏，也不递归扩展为全库审计。决策的记录与迁出由运行规则和 wrapup 负责，不在本目录另立规则。

## 关键资料的受影响条件

| 资料 | 需要检查的变化 |
| --- | --- |
| PROJECT | 全局目标、边界、总体阶段或资料入口变化 |
| 〔已有对外说明，按需保留〕 | 〔它实际描述的业务行为改变〕 |

## 项目联动关系

〔只记录实际、稳定且容易遗漏的关系，例如：报名资格变更时，检查对外报名说明的资格描述。每条一个小标题，写「触发」与「动作」：触发写什么变化，能对应到文件或目录时用反引号写出路径(如 `docs/报名规则.md`、`public/`)；只写路径的触发由脚本判断是否命中，路径之外还有文字条件的由 wrapup 自行判断；路径可用 `*` 通配(如 `chapters/*.md`)。动作写核对位置及必要依据，不重复维护正文。格式如下，下面代码块里的示例不算规则：〕

```markdown
### 报名资格变更 → 对外报名说明

**触发**:`docs/报名规则.md` 中的报名资格变化。
**动作**:核对 `public/报名说明.md` 的资格描述。
```

## 套件升级边界

修改机制实现时检查相关说明和实际宿主接线；仅在公开契约变化时更新业务 README。完整升级的必需文件全部写入并验证后才推进套件 VERSION；部分失败报告 mixed / pending，不伪装完整升级。项目二进制、素材及其他策略沿用项目自身约定，不在此强制统一。
