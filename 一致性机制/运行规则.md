# 项目一致性机制 · 运行规则

> 本项目使用项目一致性机制:git 记录"发生过什么",少量文件记录"现在成立什么",让 AI 跨会话接上进度,并在收尾时检查文件联动。
> 本文件只写**怎么运行这套机制**。catchup / wrapup 的具体步骤见各自 Skill;各类内容放在哪见 `PROJECT.md` 与 `一致性机制/文件联动目录.md`;设计理由见 `一致性机制/机制设计说明.md`。
> 〔本仓库试用版(决策 49、51),尚未进入分发版。〕

## 一、文件与分工

- `PROJECT.md`:项目入口——目标与边界、当前状态、阅读入口、关键决策。
- `AGENTS.md`:项目自己的 Agent 规则,由项目自行编写;机制只在其中放一行引用本文件。
- `CLAUDE.md`:只能是普通文件,内容精确为一行 `@AGENTS.md`;不复制规则正文、不附加第二份指令、不导入仓库外文件。
- `README.md`:面向外部读者,可选,归项目自有,不承担运行职责。
- 以上文件与本文件可以互相引用,不得互相代替。
- **项目负责人**:拍板架构与产品边界,确认同步计划、提交信息和对外发布。
- **AI**:分析问题、实现修改、回归检查、维护文档联动,并主动暴露风险。

## 二、随时生效

1. **拍板即落盘。** 发生了什么由 git 记录,不手工维护日志;但对话里产生的决定、对外对接、口头约定,git 看不见,必须立即写入文件,不等收尾。
   决策写入 `PROJECT.md`「待提交」区,写全文:决定 / 理由 / 否掉的方案 / 限定 / 取代(无则省略);编号取现有最大 + 1;提交前可直接改写。由决策产生的做法同步写进对应主题文档,并标注 `(决策 N)`。
2. **不重复记录。** 已有原文的内容(git 提交正文、`CHANGELOG.md`、主题文档)不在 `PROJECT.md` 复述,只给指针;`PROJECT.md` 只写现在成立的事。
3. **提交写明状态变化。** 提交主题行说明做了什么、状态如何变化(如"已实现但未接入"),细节写正文;正文不用提交哈希互相引用。
4. **二进制文件。** 需要版本史的栅格图走 Git LFS;设计源 / PDF / Office / 字体 / 媒体由 `.gitignore` 排除,所在目录放 `_manifest.md`,只记用途 / 来源 / 授权;二进制试稿放 `_drafts/`(已 gitignore),定稿后移到上级目录,并更新 manifest 或让 LFS 接管。破例纳入被忽略的二进制时,先 `git lfs track "<路径>"`,再 `git add -f`。〔纯代码 / 纯文字项目可忽略本条〕

## 三、何时用 catchup / wrapup

- **catchup**(Claude Code `/catchup`;Codex `$catchup`):新会话开始时,先恢复项目状态再工作;上下文被压缩后不重跑 catchup,按 `AGENTS.md` 中的压缩后指令轻量恢复。只读,不改文件;不重复读取宿主已加载的 `AGENTS.md`、`CLAUDE.md` 与本文件。
- **wrapup**(`/wrapup`;`$wrapup`):一段工作结束、会话将结束,或收到未同步改动提醒时运行。它检查联动、迁出「待提交」决策,经用户确认后本地提交,并只在 canonical branch(用户确认的主线分支)推进 `synced`;不自动推送远端。
- 收尾提醒只提醒,不代替 wrapup。

## 四、维护这套机制

- 新发现的稳定联动("改 A 必查 B")补进 `一致性机制/文件联动目录.md` Part B。
- 多个会话并行时,各用独立 branch + worktree;同一 worktree 不支持多个会话同时操作。
- 机制文件(Skill、hook、`一致性机制/` 下的文档)通过安装器升级,不在项目里手工修改。〔本仓库是套件源仓库,修改机制文件按 `AGENTS.md`「机制发版纪律」。〕
