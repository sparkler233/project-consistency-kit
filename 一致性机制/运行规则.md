# 项目一致性机制 · 运行规则

<!-- 一致性机制 version: 2026-09-30 -->

> 本项目使用项目一致性机制:git 记录"发生过什么",少量文件记录"现在成立什么",让 AI 跨会话接上进度,并在收尾时检查文件联动。
> 本文件只写**怎么运行这套机制**。catchup / wrapup 的具体步骤见各自 Skill;各类内容放在哪见 `PROJECT.md` 与 `一致性机制/文件联动目录.md`;设计理由见套件仓库 <https://github.com/sparkler233/project-consistency-kit> 中的 `一致性机制/机制设计说明.md`。
> 本文件由安装器管理,升级时整体更新,请勿手改;项目自己的规则写在 `AGENTS.md`。

## 一、文件

- `PROJECT.md`:项目入口——目标与边界、当前状态、阅读入口、关键决策。
- `AGENTS.md`:项目自己的 Agent 规则,由项目自行编写;机制只在其中放一行引用本文件。
- `CLAUDE.md`:只能是普通文件,内容精确为一行 `@AGENTS.md`;不复制规则正文、不附加第二份指令、不导入仓库外文件。
- `README.md`:面向外部读者,可选,归项目自有,不承担运行职责。
- `一致性机制/文件联动目录.md`:本项目"改了 A 必查 B"的联动规则,归项目所有,随项目维护。
- 以上文件与本文件可以互相引用,不得互相代替。

## 二、随时生效

1. **拍板即落盘。** 发生了什么由 git 记录,不手工维护日志;但对话里产生的有价值信息——决定、对外对接、口头约定,以及发现、待办和暂不处理的问题——git 看不见,必须立即写入文件,不等收尾。
   决策写入 `PROJECT.md`「待提交」区,写全文:首行 `- 日期 · 决策 N:标题`,其下每项缩进一行(`  - 决定:…`),依次为决定 / 理由 / 否掉的方案 / 限定 / 取代(无则省略);编号取现有最大 + 1;提交前可直接改写。由决策产生的做法同步写进对应主题文档,并标注 `(决策 N)`。
   发现、待办和暂不处理的问题写进它所属的位置(对应主题文档、后续想法的位置等);以后要跟进的,在 `PROJECT.md` 的状态或入口里留下能找到它的指针。
2. **不重复记录。** 已有原文的内容(git 提交正文、主题文档)不在 `PROJECT.md` 复述,只给指针;`PROJECT.md` 只写现在成立的事。
3. **提交写明状态变化。** 提交主题行说明做了什么、状态如何变化(如"已实现但未接入"),细节写正文;正文不用提交哈希互相引用。
4. **二进制文件。** 需要版本史的栅格图走 Git LFS;设计源 / PDF / Office / 字体 / 媒体由 `.gitignore` 排除,所在目录放 `_manifest.md`,只记用途 / 来源 / 授权;二进制试稿放 `_drafts/`(已 gitignore),定稿后移到上级目录,并更新 manifest 或让 LFS 接管。破例纳入被忽略的二进制时,先 `git lfs track "<路径>"`,再 `git add -f`。〔纯代码 / 纯文字项目可忽略本条〕

## 三、何时用 catchup / wrapup

- **catchup**(Claude Code `/catchup`;Codex `$catchup`):新会话开始时,先恢复项目状态再工作;上下文被压缩后不重跑 catchup,按 `AGENTS.md` 中的压缩后指令轻量恢复。只读,不改文件;不重复读取宿主已加载的 `AGENTS.md`、`CLAUDE.md`;本文件不依赖宿主导入,由 catchup 读取。
- **wrapup**(`/wrapup`;`$wrapup`):一段工作结束、会话将结束,或收到收尾提醒时运行;用户说「收尾」就是运行 wrapup。它检查联动、迁出「待提交」决策,本地提交(在主线上先经用户确认),并只在 canonical branch(用户确认的主线分支)推进 `synced`;不自动推送远端。需要整理项目文档时,明确告诉 wrapup 整理。
- 收尾提醒只提醒,不代替 wrapup。

## 四、维护这套机制

- 新发现的稳定联动("改 A 必查 B")补进 `一致性机制/文件联动目录.md`。
- 多个会话并行时,各用独立 branch + worktree;同一 worktree 不支持多个会话同时操作。主线上没有会话,用户说「并进主线」时由这个会话自己合并。并行只守三条,其余怎么做由用户与宿主决定:
  - 主线只通过检查过的合并前进,不改写主线历史;
  - 停下时,把这项工作的现状(目标、进度、还剩)写进分支上的检查点(分支上的 wrapup 提交);
  - 只写自己的分支和 worktree,不动别人的分支和未提交改动。
- 并行的 Git 操作由 `node .agents/skills/wrapup/scripts/task.mjs` 完成:同步主线用 `sync`(不手抄主线的改动),并进主线用 `land`,用法见 `--help`。分支上不改 `PROJECT.md` 的总体状态与阅读入口,并进主线时一起更新。
- 机制文件——`.agents/skills/` 下的 Skill 与脚本、`.agents/hooks/`、宿主入口与接线(`.claude/commands/`、`.claude/settings.json` 与 `.codex/hooks.json` 中机制的 hook 项:收尾提醒、每轮提示、压缩后提醒),以及 `一致性机制/` 下除文件联动目录以外的文件——通过安装器升级,不在项目里手工修改。
